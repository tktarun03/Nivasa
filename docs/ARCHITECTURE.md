# Architecture

## Pages and boot

Each page is a real HTML entry (`index.html`, `pages/<name>/index.html`) with static structure and one module in `src/js/pages/`. Every module calls `bootPage({ page, back }, init)` from `src/js/app.js`, which:

1. applies saved preferences (theme, text scale, motion, language),
2. renders the shared shell (skip link, header with live status, adaptive bottom nav, footer),
3. runs the page's `init`, with an error state if it throws,
4. starts scroll motion, path drawing and tilt,
5. shows onboarding on first launch, otherwise a one-time “Updated to version X” notice,
6. registers the service worker (production only).

Vite builds every folder in `pages/` automatically (`vite.config.js`). `base: './'` keeps all URLs relative.

## Data model

```
categories.json   groups[] { id, name, scope, items[] { id, name, keywords[] } }, cities[], climates[], budgetTiers[]
styles.json       styles[] { id, name, origin, kind: regional|global, summary, signature[], materials[], palette{} }
designs.json      designs[] { id, title, summary, category, style, city, climate, property, budgetTier,
                              budget { low, high, basis }, areaSqft, elements[], materials[],
                              images[] { src, width, height, view, alt }, credit, license, demo, featured, added, popularity }
materials.json    groups[], materials[] { id, name, group, description, uses[], pros[], cons[], maintenance, cost, standards[], standardsNote? }
standards.json    tiers[], reviewStatuses[], documents[] { id, designation, title, authority, edition, tier, scope,
                              applicability, reviewStatus, verifiedOn, sources[] { name, url }, section?, notes? },
                  guidance[] { id, tier, topic, title, body, reviewStatus, related? }
collections.json  collections[] { id, title, summary, rule { field: [values] } }
```

`designs.json` is generated by `scripts/seed-catalogue.mjs` (budgets come from the same model as the planner). Illustrations are generated from each design and its style palette by `scripts/generate-art.mjs` → `public/assets/illustrations/designs/<id>-<n>.svg`.

## Saved data (localStorage key `iis.data`)

```
{ schema: 1,
  prefs { city, propertyType, bedrooms, style, budget, interests[], units, theme, textScale, motion, haptics, language, brandName, keepPortrait },
  onboarding { done, at }, favourites[], boards[] { id, name, createdAt, coverLock?, items[] { designId, imageIndex, locked, addedAt } },
  photoLocks { designId: imageIndex }, budgetDraft, budgetUsed, recent[], checklistHidden, lastSeenVersion, installedVersion }
```

`migrate()` fills defaults for any missing field. `store.update()` writes synchronously; if the write fails, state rolls back and a “Couldn't save” notice offers a backup.

## Versioning

`package.json` `version` is the single source; Vite injects it as `__APP_VERSION__`. `src/js/releases.js` holds the in-app notes and `CHANGELOG.md` the repository notes; a unit test keeps all three aligned. The service worker cache name includes the version.
